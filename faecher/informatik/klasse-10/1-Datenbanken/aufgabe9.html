Merke: Datenpflege und Transaktionen

Daten müssen gepflegt werden: Datensätze werden eingefügt, geändert und gelöscht. Das nennt man Datenpflege.

Eine Transaktion besteht aus einer oder mehreren Datenbankoperationen, mit denen Daten eingefügt, geändert oder gelöscht werden. Sie soll fehlerfrei ausgeführt werden: Danach müssen die Daten in der Datenbank stimmig sein.

CRUD fasst die vier Grundoperationen zusammen:

  • Create (erstellen) – INSERT
  • Read (lesen) – SELECT
  • Update (ändern) – UPDATE
  • Delete (löschen) – DELETE

Nur SELECT verändert den Datenbestand nicht.

INSERT INTO tabelle (spalte1, spalte2)
VALUES (wert1, wert2)

UPDATE tabelle
SET spalte = wert
WHERE bedingung

DELETE FROM tabelle
WHERE bedingung

Achtung: Ohne WHERE ändert UPDATE bzw. löscht DELETE alle Zeilen der Tabelle.

Beim Ändern von Daten können Inkonsistenzen (= Unstimmigkeiten) entstehen. Solche Fehler bei der Datenpflege nennt man Anomalien.

Neles Name steht dreimal in der Tabelle, geändert wurde er aber nur einmal. Mit WHERE username = 'nelefitmuse' hätte es geklappt – aber nur, weil man daran gedacht hat. Bei Redundanz muss jede Änderung alle Kopien treffen.

Beim Einfügen von Daten können relevante Informationen fehlen.

Merke: Integrität

Integrität (lat. integritas) bedeutet »Unversehrtheit«. Bei Änderungen der Daten muss die logische Übereinstimmung in der Datenbank erhalten bleiben.

Ein Datenbanksystem fordert dafür Bedingungen, die Integritätsbedingungen. Sind sie erfüllt, ist die Datenbank konsistent (stimmig): Es gibt keine widersprüchlichen Datensätze. Verstößt eine Anweisung gegen eine Integritätsbedingung, führt das Datenbanksystem sie nicht aus.

  • Integrität mit Primärschlüssel (Entitätsintegrität): Der Primärschlüssel muss eindeutig sein – keine zwei Datensätze mit gleichem Primärschlüsselwert –, und er darf nicht den Wert NULL annehmen. Beispiel: Anweisung A.
  • Wertebereichsintegrität: Attributwerte dürfen nur im festgelegten Wertebereich liegen, also den richtigen Datentyp haben. Beispiel: Anweisung B.
  • Referentielle Integrität (Integrität der Beziehungen): Zu jedem Fremdschlüssel gibt es einen zugehörigen Datensatz mit gleichem Primärschlüsselwert. Grundregel: Fremdschlüssel müssen immer auf existierende Datensätze verweisen. Beispiel: Anweisung C.

Integrität ist nicht dasselbe wie Datenschutz: Wer Daten sehen oder ändern darf, regeln Benutzerrechte.

Transaktionen und Integrität auf einen Blick

Hier siehst du die Merksätze und die richtigen Ergebnisse aller sieben Lernschritte.

Transaktionen

INSERT · UPDATE · DELETE

Eine oder mehrere Datenbankoperationen, die Daten einfügen, ändern oder löschen. Danach müssen die Daten stimmig sein. CRUD: Create, Read, Update, Delete.

Anomalien

users_photos

UPDATE-Anomalie: Beim Ändern entstehen Inkonsistenzen. DELETE-Anomalie: Beim Löschen geht mehr verloren als gewollt. INSERT-Anomalie: Beim Einfügen fehlen relevante Informationen. Ursache: Redundanz.

Integritätsbedingungen

Primärschlüssel · Datentyp · Fremdschlüssel

Entitätsintegrität: Primärschlüssel eindeutig und nie NULL. Wertebereichsintegrität: Wert im festgelegten Wertebereich. Referentielle Integrität: Fremdschlüssel verweist auf einen existierenden Datensatz.
