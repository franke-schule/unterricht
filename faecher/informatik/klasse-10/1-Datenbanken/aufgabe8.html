2

Verstehen

Wohin kommt der Fremdschlüssel?

Bei einer 1:n-Beziehung steht der Fremdschlüssel auf der n-Seite. Bei Klasse 1 ───── 1 Klassenleiter gibt es aber keine n-Seite.

Der jeweilige Fremdschlüssel kann in die eine oder die andere Klasse eingefügt werden, aber nicht in beide Klassen.

Wähle alle Schemata aus, die die 1:1-Beziehung richtig umsetzen.

Hilfe 1

Vergleiche, in welcher Tabelle jeweils ein Attribut mit eckigen Klammern steht.

Hilfe 2

Bei 1:n muss der Fremdschlüssel auf die n-Seite, weil dort jeder Datensatz genau einen Verweis braucht. Bei 1:1 haben beide Seiten nur genau einen Partner.

Hilfe 3

Schema A speichert die Verbindung genau einmal und ist richtig. Prüfe, ob das für Schema B genauso gilt und was in Schema C anders ist.

Merke: 1:1-Beziehung umsetzen

1:1-Beziehungen sind ein Sonderfall der 1:n-Beziehung. Der Fremdschlüssel kann in einer der beiden beteiligten Klassen (bzw. Tabellen) hinzugefügt werden.

Er steht aber nur in einer Tabelle – sonst wäre die Verbindung doppelt gespeichert.

Übertragen: Schlüssel und Schloss

In einer Schließanlage öffnet jeder Schlüssel genau ein Schloss. Zu jedem Schloss gehört genau ein Schlüssel.

Ergänze die Kardinalitäten.

Notiere beide möglichen Tabellenschemata, um die 1:1-Beziehung umzusetzen.

Schreibe in jedes Feld beide Tabellen untereinander und jede Spalte in eine eigene Zeile. Die Reihenfolge der Tabellen und Attribute ist egal.

Hilfe 1

Jede Möglichkeit besteht aus beiden Tabellen. Übertrage zuerst die Attribute der Klassenkarten mit ihren Datentypen.

Hilfe 2

Die Beziehung öffnet wird durch einen Fremdschlüssel umgesetzt. Du schreibst ihn wie user_id[users]: int: in den eckigen Klammern steht die Tabelle, auf die er verweist.

Hilfe 3

In einer Möglichkeit bekommt schluessel die Zeile schloss_id[schloss]: int. In der anderen steht der Fremdschlüssel stattdessen in schloss.

n:m-Beziehung

Können auf beiden Seiten viele Objekte beteiligt sein, spricht man von einer n:m-Beziehung.

Hier: Schüler  n ───── m  AG. Man verwendet zwei verschiedene Buchstaben, weil die beiden Anzahlen unabhängig voneinander sind.

Mit nur einem Fremdschlüssel lässt sich eine n:m-Beziehung nicht umsetzen.

Ergänze die Kardinalitäten bei »kann liken«, »kann kommentieren« und »kann folgen«.

Hilfe 1

Lies jede Beziehung in beide Richtungen, z. B.: Wie viele Fotos kann ein Benutzer liken? Von wie vielen Benutzern kann ein Foto geliked werden?

Hilfe 2

Stehen in beiden Richtungen »viele«, ist es eine n:m-Beziehung. Verwende dann zwei verschiedene Buchstaben.

Hilfe 3

»kann liken« ist eine n:m-Beziehung. Prüfe »kann kommentieren« und »kann folgen« genauso. Bei »kann folgen« sind beide Enden an users: Ein Benutzer kann vielen folgen und viele Follower haben.

Richtig: users n ───── m photos (kann liken, kann kommentieren) und users n ───── m users (kann folgen). Im Klassendiagramm bleibt jede n:m-Beziehung eine einzige Linie.

Die Hilfstabelle likes

Für die Likes bekommt InstaHub die Hilfstabelle likes.

  id: int
  photo_id[photos]: int
  user_id[users]: int

  updated_at: date
)

Wer hat Foto 14 geliked?

  …

  id: int

Ergänze die Kardinalitäten. So wird users n ───── m photos mit Tabellen umgesetzt.

Hilfe 1

Die Spalte user_id in likes verweist auf users, die Spalte photo_id auf photos.

Hilfe 2

Achtung: photos.user_id gibt an, wer ein Foto hochgeladen hat. Wer ein Foto geliked hat, steht nur in likes.

Hilfe 3

Für die Kardinalitäten: Jede Zeile in likes enthält genau eine user_id und genau eine photo_id. Der Fremdschlüssel steht immer auf der n-Seite.

Richtig: users 1 ───── n likes n ───── 1 photos. Ein Benutzer kann viele Likes vergeben, ein Foto viele Likes bekommen. Jede Zeile in likes gehört zu genau einem Benutzer und genau einem Foto.

Übertragen

Die Hilfstabelle follows

Auch Follower speichert InstaHub in einer Hilfstabelle. follower_id: wer folgt · following_id: wem gefolgt wird.

follows(
  id: int
  following_id[users]: int
  follower_id[users]: int
  created_at: date
  updated_at: date
)

follower_id: wer folgt · following_id: wem gefolgt wird

Entscheide: Was bedeutet die Zeile mit id 947?

zornigerfotograf und reisejoule folgen sich gegenseitig. Kreuze an, was stimmt.

Hilfe 1

Beachte die Erklärung über der Tabelle: follower_id ist der, der folgt. following_id ist der, dem gefolgt wird.

Hilfe 2

Übersetze jede id mithilfe von users in einen Benutzernamen und lies die Zeile dann als Satz: »follower folgt following«.

Hilfe 3

Zeile 1 heißt: reisejoule folgt zornigerfotograf. Vergleiche damit Zeile 2.

Richtig: follows ist die Hilfstabelle zu users n ───── m users. Beide Fremdschlüssel verweisen auf users, und jede Zeile beschreibt eine Richtung. In InstaHub sind likes, comments und follows solche Hilfstabellen.
